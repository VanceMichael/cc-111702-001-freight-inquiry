# 运价询盘工作台
本项目用于按给定地址和货物向承运商查询报价，拆出必收费用后列出候选。除一次标准询价外，还支持承运商在询价过程中提出条件修正（补填楼层、把地址拆成干线和末端两段、只接受部分货物）的交互式询价：每次出价同时保留用户原始条件与承运商实际接受的条件，只有用户事先允许的等价修正会自动继续，超出授权的条件等待采购确认，不替用户同意。
运行环境为 Node.js 22.23.4，仅使用标准库，没有运行时安装步骤。数据均为本地合成资料，默认来源只监听回环地址，不连接真实业务网站或真实账号。
## 运行
```bash
npm run build
npm test
npm run demo
```
演示会在进程内启动实际本地 HTTP 来源，先办理一次标准询价，再办理一次承运商提出条件修正、采购确认后来源重新计价的交互式询价，打印领域结果及来源请求，然后关闭服务。端口由系统分配，数据保存在内存，不影响已启动的服务。
持续运行时先执行 `npm run source`，再在另一个终端执行 `npm start`。默认来源端口为 4101，业务端口为 4100；可通过 `SOURCE_URL`、`PORT` 和 `STATE_PATH` 指定回环来源、端口及状态文件。终止进程使用 Ctrl+C。删除 `var/` 可清空本地持久状态。
## 业务接口
`POST /collect` 接收本次办理参数，空对象使用本地样例的正常条件；`allow` 给出本次事先允许的等价修正（如 `{"kind":"floor"}`、`{"kind":"addressSplit"}`、`{"kind":"pieces","min":2}`），`now` 指定判定时间。`POST /confirm` 对待确认报价作出采购决定（`decision` 为 `accept` 或 `reject`）；确认前重新读取来源报价，以来源当前版本与价格成交，来源条件已变化时不替采购同意。`POST /refresh` 重新读取指定报价的来源当前状态，用于恢复未完询价或补领费用。`GET /state` 查询当前业务结果，可用 `?now=` 指定判定时间；`GET /health` 查询服务状态。一次办理失败不会提交中间业务状态，接口以 422 返回拒绝原因。状态文件按完整写入后替换，单进程内串行办理。
- `inquiries`：保存询盘条件、等价修正授权与询盘代次，判断新询盘身份；采购修改件数或送货要求后进入新代次，旧条件结果与旧确认不套用到新询盘。
- `terms`：比对用户原始条件与承运商接受条件，判定授权内等价修正。
- `charges`：核算单一报价的已知费用完整性；附加费用领取失败记为不完整，不按零元处理。
- `comparison`：按判定时间区分可比较候选与未确认线索，候选注明比较依据（标准报价、授权内修正、采购确认），线索说明原因；同一时间不可比较的价格不拼成组合报价。
来源接口的字段约定见 `docs/source-contract.md`。`fixtures/source.json` 是可独立启动的来源响应数据，来源 `GET /trace` 返回实际请求；脚本每条路由依次返回响应，超出后重复最后一条，可表达延迟、断连和明确拒绝。请求轨迹只记录是否带授权，不回显授权原文。
## 测试
测试覆盖领域正常结果、状态重开、HTTP 办理与查询、来源拒绝后的回滚、并行存储更新、本地访问边界和来源请求追踪，以及交互式询价的授权内修正、待确认线索、确认时重新计价、确认期间报价到期、附加费用领取失败、询盘变更后旧确认不套用、恢复未完询价不沿用旧授权。每个测试使用临时端口与独立状态，不依赖执行顺序。构建仅检查源码语法，不获取依赖。
