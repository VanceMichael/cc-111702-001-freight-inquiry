# 业务运行边界
当前可查询：询盘条件与代次、报价费用与条件差异、可比较候选与未确认线索。
当前写入操作：标准询价、交互式询价（承运商条件修正）、采购确认或拒绝、报价刷新。
只包含明确费用的报价进入候选；附加费用领取失败的报价记为不完整线索，不按零元比较。

## 原始依据
来源请求保存方法、路径、状态、字节数与响应摘要，不保存授权原文。拒绝或不完整响应不能作为领域收件成功；业务结果和请求收据分别可查。进程内的写入序列只保证本进程存储互斥，不代表来源具备幂等或多进程协调能力。

## 领域决定
询盘职责决定询盘身份与代次，询盘条件变更后旧报价与旧确认不套用到新询盘；条件职责比对用户原始条件与承运商接受条件，只有用户事先允许的等价修正自动继续，其余等待采购确认，不替用户同意；费用职责决定费用可接纳性与完整性；比较职责在接纳前裁定有效期与费用完整，并按判定时间区分可比较候选与线索，不把不合条件报价放入候选，也不把同一时刻不都成立的价格拼成组合报价。
采购确认以来源当前版本与价格成交，确认后来源重新计价或改变条件的，旧确认不自动适用于新版本。恢复未完询价时同样按来源当前状态重新判定，不把旧确认当作新授权。
这些拒绝属于当前正常办理契约，不代表来源失败可视为业务成功。各决定在状态提交前完成，拒绝不会消耗本地办理状态。
